# Acorn audit + rewrite plan

_Audit date: 2026-07-15. Reviewed `bin/acorn` (3,226 lines), the 4 skills, README, command doc, global CLAUDE.md, tests, and the local Codex/Fable surface._

## Verdict

The core idea holds and is more valuable now than at build time: issue → grounded, red-teamed spec before code. But the implementation is built around 2025 constraints that no longer apply. About a third of the script (~1,000 of 3,226 lines) exists only to coax an interactive orchestrator into behaving and to screen-scrape a tmux TUI. The model assignments predate Fable 5, Opus 4.8, Sonnet 5, and a usable Codex CLI, and the "diverse drafting" stage isn't actually diverse (all four drafters are the same model with different prompts). There are also two real bugs that bite today, independent of any rewrite.

---

## Tier 1 — bugs that bite now (fix regardless of any rewrite)

1. **`deps graph` is broken for multiple issues.** Global `IFS=$'\n\t'` (bin/acorn:3, space removed on purpose) collides with `topological_sort_waves`, which builds space-joined strings (bin/acorn:455,489,508) and iterates them with unquoted `for candidate in $remaining` (bin/acorn:473,503,509). With space out of IFS, `"1 2 3"` is one token, so every issue collapses into a single mangled Wave 1 and dependency ordering is ignored. Single-issue input works, which hid it. This feeds the `acorn-orchestrate` wave planner, so the breakage is load-bearing.

2. **The tmux readiness poll never matches on macOS.** `wait_for_claude_ready` (bin/acorn:1667-1687) uses GNU-isms: `sed 's/\x1b\[.../'` and `grep -E '>\s*$'`. BSD `sed`/`grep` (this is darwin) don't honor `\x1b`/`\s`, so the ANSI strip is a no-op and the prompt never matches → always times out at 30s → always falls through to "send the trigger anyway." The auto-trigger works only by accident of the fallback, on a fixed `sleep 1` (bin/acorn:1700) timing hack.

3. **The orchestrator is told the wrong pipeline shape.** The methodology text emitted into PROMPT.md says "5-stage" and "13 Task agent launches" / "13 sub-agents" (bin/acorn:538,560,570,982), but the actual overview lists 3+4+1+1+4+1 = 14 across Stage 0–5 (6 stages), and usage at bin/acorn:46 says 14. The agent literally reads the wrong totals. Lite has the same class of error (bin/acorn:995 "3-stage" vs :1021 "4 stages"). This misinforms the running orchestrator, not just docs.

4. **Stale hardcoded model ID, live in a code path.** `analyze_issue_for_split` defaults to `claude-sonnet-4-5` (bin/acorn:2485, again at :2784), used by the only real LLM call `claude -p --model "$model"` (bin/acorn:2531). That's a generation behind Sonnet 5. For a JSON classification ("should this split?") Fable 5 is the better tier now anyway. Also stale: a `claude-opus-4-6` doc example (README:450) — that ID never existed under current naming.

5. **Split analysis screen-scrapes JSON instead of asking for it.** `analyze_issue_for_split` calls `claude -p` without `--output-format json`, then runs a 3-tier fallback scraper (raw jq → ```json fence → generic fence) and dies if none parse (bin/acorn:2539-2561). Contradicts your own "use `--output-format json`" rule; structured output deletes all three fallbacks.

## Tier 2 — staleness (cheap corrections)

- **Context-scarcity scaffolding is obsolete.** "Sub-agents have their own 200k token contexts. You do NOT" (bin/acorn:976,1243,1422) is false for Opus 4.8 [1m] (1M). "Write in chunks of ~4000 tokens max (Write then Edit to append)" is repeated ~20× (bin/acorn:594,613,658,1053,1127,1318,…) — a workaround for old Write limits that now just adds Edit round-trips and slows every sub-agent.
- **Recon burns the top tier.** Full-mode recon uses `opus` (bin/acorn:576) to scan a codebase; lite/quick correctly drop to `sonnet` (bin/acorn:1035,1300). Recon is exactly Fable/Haiku work.
- **No doc mentions Fable or Haiku at all**; the tier language (README:11-17,481-510; command doc:23-29,173-200; global CLAUDE.md:8-12) is Opus/Sonnet-only.
- **Docs describe backends that never exist.** `status` BACKEND column claims `tmux`/`dev`/`pi` (README:306, command doc:169) but `write_meta_json`/`start_session` only ever emit `tmux` (bin/acorn:2130,1660). README's SESSION column omits the real `no-session` state (bin/acorn:1733-1754).
- **`orchestrate` skill watches a dead signal.** It treats a session as done when status shows `review` (SKILL.md:174), but `status_for_spec` only returns `review` for *unlabeled* legacy issues (bin/acorn:1818-1857); anything acorn touched sits at `spec-in-progress` until a human runs `spec-complete`. Completion check should key off `plans/SPEC.md` or the `spec-review` label instead.
- **`setup` skill lacks YAML frontmatter** that the other three have (odd one out).

## Tier 3 — architecture: ~35% of the script is scaffolding the platform now owns

Line accounting of "make an interactive orchestrator behave" vs real CLI logic:

| Bucket | Lines | ~count |
|---|---|---|
| `planning_block_{full,lite,quick}` + dispatcher (the methodology prose) | 519-1431 | ~910 |
| PROMPT.md assembly/validation + completion-protocol heredoc | 14-22, 1433-1495 | ~90 |
| tmux launch + TUI-scrape trigger (`start_session`, `wait_for_claude_ready`, `send_auto_trigger`, session_state/attach scraping) | 1639-1765 | ~130 |
| `analyze_issue_for_split` JSON-scrape fallback | 2539-2561 | ~25 |

That's ~1,150 lines whose only job is to (a) hand-write an orchestration methodology as English the agent is *begged* to follow ("you have FAILED", "DO NOT write a plan yourself"), (b) launch a detached TUI and screen-scrape it to readiness, and (c) reverse-engineer structure back out of free-text output. The three `planning_block_*` functions are ~70% duplicated verbatim (the recon block is byte-identical across all three except `opus`→`sonnet`).

The remaining ~65% is genuine, valuable CLI logic orthogonal to how agents are orchestrated: the GitHub label lifecycle state machine, the dependency API + graph + Kahn scheduler, `issue create/plan/split/depends`, `list`/`status`, image extraction/download, `clean/approve/spec-complete`. **This survives any rewrite intact.**

## The heterogeneous panel — the real capability upgrade

Today all four Stage-1 drafters are told `Use model "opus"` (bin/acorn:646); "diversity" is entirely in the lens prompt. Genuine diversity comes from different model *families* reasoning differently about the same problem. All the pieces are present and authed locally:

- **Claude**: `claude -p --model {fable|sonnet|opus} --output-format json`
- **Codex**: `codex exec -m gpt-5.6-sol --skip-git-repo-check -a never -o <file>` (or `--json` for token accounting, `--output-schema <file>` for constrained JSON). Authed via ChatGPT subscription — matches your no-API-keys rule.

Proposed per-node assignment (full pipeline):

| Stage | Node(s) | Today | Proposed |
|---|---|---|---|
| 0 Recon | 3× explore | Opus | **Fable 5** (fast, cheap, high-context scan) |
| 1 Draft | Minimal Surgery | Opus | **Codex `gpt-5.6-sol`** (surgical precision) |
| 1 Draft | Clean Architecture | Opus | **Opus 4.8** |
| 1 Draft | Robustness/Edge | Opus | **Sonnet 5** |
| 1 Draft | DX/Pragmatic | Opus | **Fable 5** |
| 2 Evaluate | 1× judge | Opus | **Opus 4.8** (optionally 2 judges Opus+Codex, averaged, to blunt same-family self-preference) |
| 3 Synthesize | 1× | Opus | **Opus 4.8** |
| 4 Red team | 4× adversary | Opus | **Codex / Opus / Sonnet / Fable** (cross-family catches failure modes redundancy can't) |
| 5 Final spec | 1× | Opus | **Opus 4.8** |

Net effect: cheaper recon, genuinely diverse drafts, cross-family adversarial review, top-tier reasoning reserved for synthesis/spec. This is the single change most likely to raise spec *quality* rather than just move cost around.

Trade-off to accept: a hard dependency on the Codex CLI being installed and authed, plus per-model prompt dialects (Codex wants compact, XML-tagged operator prompts per the `gpt-5-4-prompting` plugin skill; Claude wants prose). Both are manageable; degrade gracefully to Claude-only if `codex` is absent.

## Rewrite plan (phased, each phase independently shippable)

### Phase 0 — fixes (no architecture change, ~half a day)
- Fix the `IFS`/wave-scheduler bug (quote or re-split explicitly in `topological_sort_waves`).
- Fix the 14/6 vs 13/5 counts in `planning_block_full` and the lite header.
- Bump `claude-sonnet-4-5` → Fable for split analysis; add `--output-format json` and delete the 3-tier scraper.
- Fix docs: BACKEND is always `tmux`; add `no-session`; drop the `claude-opus-4-6` example.
- Point the `orchestrate` skill's completion check at `plans/SPEC.md` / `spec-review`.
- Make the tmux readiness poll BSD-safe (or moot it in Phase 2).

### Phase 1 — model dispatcher + heterogeneous panel (the upgrade)
- Introduce one `run_agent(model, prompt, out_file, [schema])` dispatcher that routes by model name: `claude-*`/`fable`/`sonnet`/`opus` → `claude -p`; `gpt-*`/`codex*` → `codex exec`. Single source of truth for model selection (replaces 12 frozen-in-prose sites).
- Move per-stage model choice from methodology prose into a declarative table (the panel above).
- This is testable: stub the dispatcher and assert which model each stage requests — the seam that has zero coverage today.

### Phase 2 — replace tmux orchestration with a headless orchestrator
The current "generate PROMPT.md + launch detached Claude in tmux + send-keys the trigger" is the fragile part and the part that can't do heterogeneous fan-out (a Claude Task-tool orchestrator can't launch Codex agents). Two options:

- **(Recommended) Standalone headless orchestrator** (small Python run via `uv`, or Node): acorn's bash keeps all the GitHub/label/deps/image plumbing; the pipeline becomes a deterministic staged fan-out that shells out to `claude -p` and `codex exec` in parallel, writing `recon/*.md` and `plans/*.md` artifacts to disk exactly as now. Deletes ~1,000 lines of scaffolding (tmux dance, planning-block prose, PROMPT.md coercion, JSON scraper). Fire-and-forget, testable, heterogeneous-native, no interactive session required.
- **(Alternative) Claude Code Workflow tool**: deterministic `pipeline()`/`parallel()` with structured outputs, Codex nodes shelling out via Bash. Cleaner *if* acorn runs inside a Claude Code session, but it's Claude-centric and needs a live session, which doesn't fit a detached `acorn create`. Better suited if you'd rather drive the pipeline interactively than as a background CLI.

Keep the file artifacts (`recon/`, `plans/`, red-team reports) regardless — they're worth it for auditability and the `spec-review` skill already reads them.

### Test strategy for the rewrite
- Label/split/deps suites are rewrite-safe scaffolding — keep them.
- `test_auto_trigger.sh` (readiness sentinel + send-keys assertions) dies with the tmux layer — replace with dispatcher tests.
- Add the missing coverage the current suite entirely lacks: that each stage requests the right model, and that a run produces the expected artifacts. A green suite today would NOT prove the new orchestration works, because the model-dispatch seam is untested.

---

## Recommended sequence

Phase 0 now (real bugs, cheap). Then Phase 1 (dispatcher + panel) as the headline capability win, which also makes Phase 2 tractable. Phase 2 last, since it's the largest change and the payoff (deleting the tmux fragility) compounds with Phase 1 rather than blocking it.
